# قواعد العمل المعتمدة — LAST FRONTIER: CROWNFALL
تاريخ الاتفاق: 2026-10-19

> هذا المستند يوثّق توجيهات مالك المشروع للعمل الآمن. ليس مستودعًا للأسرار ولا يحل محل السياسات الرسمية للمنصات. يرجى مراجعة آخر تعليمات المالك في كل جلسة.

## 1. الالتزام بسياسات الخدمات
- العمل وفق شروط وسياسات GitHub وEpic Games وGoogle Play وكل خدمة نستخدمها؛ الرجوع للوثائق الرسمية عند الشك.
- عدم التحايل على حدود الاستخدام، أو التقييدات، أو وسائل الأمان، أو سياسات الخدمة.
- لا يوجد ضمان بأن أي عمل لن يؤدي إلى تقييد من المنصة؛ نخفّض المخاطر بالمراجعة وضبط حجم الأنشطة.
- تجنّب الطلبات الآلية المفرطة، وإعادة تشغيل GitHub Actions دون سبب، والرفع المتكرر غير الضروري.

## 2. تفويض العمل المعتاد على GitHub
وافق المالك على إتمام مهام GitHub المعتادة دون طلب موافقة منفصلة لكل خطوة، وتشمل:
- الاطلاع على الملفات والفروع والالتزامات وطلبات الدمج وسجلات Actions المتاحة.
- تحليل الأعطال، وإعداد إصلاحات برمجية محددة، وإنشاء فرع منفصل والتوثيق والالتزامات وطلبات الدمج عند الحاجة.
- تشغيل تحقق محدود وضروري فقط بعد تقييم الموارد والتكلفة ومراجعة شروط استخدام GitHub، مع عدم تكرار البناء المكلف بلا مبرر.
- تقديم تقرير موجز عمّا فُحص وما تغيّر، وروابط الالتزامات ونتائج الاختبارات المؤكدة.

**استثناءات عالية الأثر تحتاج تأكيدًا خاصًا قبل التنفيذ:**
حذف نهائي، force-push أو إعادة كتابة تاريخ الفروع، تغيير صلاحيات أو سياسات الأمان، نشر إصدار عام أو رفعه إلى المتاجر، نقل بيانات حساسة، إنشاء نفقات أو موارد مدفوعة كبيرة، أو أي إجراء لا رجعة فيه.

## 3. الحماية من فقدان العمل
- افحص آخر حالة حقيقية في GitHub والمصادر المتاحة قبل الكتابة؛ لا تعتمد على سجلات قديمة فقط.
- حافظ على ملفات المشروع الأصلية وتقدم المالك؛ استخدم فروعًا مستقلة ومراجعة فروق التعديلات.
- لا تستبدل ملفات Unreal الثنائية (مثل .umap) بقيم مُختلَقة؛ استخدم أدوات Unreal الرسمية، واحتفظ بنسخة أصلية قبل أي تعديل.
- لا تدمج تغييرات غير مختبرة على الفرع الأساسي دون مراجعة مناسبة.
- لا تعتبر Compile أو Cook أو Package أو Smoke Test ناجحًا إلا بدليل نجاح فعلي؛ فرّق بين الاختبار الثابت والبناء الحقيقي.

## 4. إدارة المفاتيح وكلمات المرور
- لا تُحفظ **القيم** السرية في هذا الملف أو Git أو سجل المحادثة أو التقارير أو لقطات الشاشة.
- احتفظ فقط بأسماء الأسرار والمراجع اللازمة، وأبقِ القيم الفعلية في GitHub Actions encrypted Secrets، أو مدير أسرار معتمد، أو مخزن مفاتيح محلي محمي.
- استخدم أقل الصلاحيات، وأبقِ مفاتيح التوقيع (JKS) وكلمات مرورها خارج المستودع والأوامر الظاهرة في السجلات.
- إذا ظهرت قيمة سرية علنًا أو في سجل، أوقف استخدامها وابدأ إجراءات إلغائها/تدويرها بعد تقييم المخاطر.
- أمثلة أسماء أسرار سابقة بلا قيم: `CROWNFALL_UPLOAD_KEYSTORE_B64`, `CROWNFALL_UPLOAD_STORE_PASSWORD`, `CROWNFALL_UPLOAD_KEY_ALIAS`, `CROWNFALL_UPLOAD_KEY_PASSWORD`, `EPIC_GHCR_USER`, `EPIC_GHCR_TOKEN`.

## 5. مراجعة السجلات، واستهلاك الموارد
- ابدأ بفحص آخر checkpoint ونتائج Actions والملفات المعنية بدل تشغيل مئات الاختبارات.
- طبّق فحوصًا ساكنة صغيرة أولًا، ثم تشغيل بناء واحد موجّه عندما توجد فرضية إصلاح قابلة للتحقق.
- استخدم قيود concurrency والمسارات المحفّزة للـworkflow عند ملاءمتها، ولا تعيد المحاولة تلقائيًا عند rate limit أو أية إشارة إلى تقييد الحساب.
- احترم الحدود والتكاليف الخاصة بـ GitHub Actions، واترك فترات انتظار عندما يكون تشغيل المتكرر غير ضروري.

## 6. نقطة الاستئناف — تحتاج تحققًا مستمرًا
- المستودع: `shami0112091997-sys/LAST-FRONTIER-CROWNFALL`.
- الفرع المرجعي المتقدم وقت إعداد الاتفاق: `m66-smart-recovery`، أحدث التزام مفحوص `0aeb7fe30b68e0d266db94f8a8468bc4d434b7b9` (سجل M108، بوابة تدقيق M109 للتوقيع).
- على الفرع المنفصل `m60-unreal-first-playable` ظهر فشل Cook سابقًا نتيجة خطأ serialization في `TestMap.umap`. هذه **نتيجة تاريخية** وليست دليلًا على أن جميع الفروع لا تزال تعاني العطل.
- يوجد عمل بناء/توقيع Android منفصل؛ تحقق من سجلات البيئة المصدرية قبل اعتبار AAB صالحًا للتوزيع.
- لا تفترض أن `RECOVERY_STATE.json` يعكس أحدث تقدم؛ قد يصف حالة M47 الأقدم.
